## v1 scope

- Dataset authoring and immutable versioning
- Benchmark composition and immutable versioning
- Model execution against real LLM providers (Gemini, Groq, Mistral, NVIDIA NIM, Ollama; Grok disabled pending model validation)
- Reference-based evaluation with pluggable strategies
- Metrics, reports (incl. export), and snapshot-based leaderboards
- Agentic assistant layer (tools for datasets, benchmarks, execution, evaluation) with provider failover
- JWT authentication + permission-scoped RBAC, multi-tenant organizations/projects
- Outbox-driven execution with an eager worker (no broker required)
- Local, cloud, and persistent-VM execution modes (shared engine)

## Production architecture

```text
Atlas Web (Vercel)  →  Atlas API (Vercel, FastAPI serverless)  →  Supabase PostgreSQL
                                                                        ↓ (outbox)
                                        Atlas Worker (Render, eager Celery + sweep loop)
                                                                        ↓
                                        LLM providers → evaluation → reports → leaderboard
                                                                        ↓
                                                                  Supabase (results)
```

- **RLS**: row-level security enabled, default-deny on backend-only tables.
- **JWT auth**: HS256 tokens on all `/api/v1` routes except auth/health.
- **Supabase pooler**: API connects via pooler (`:6543`, transaction mode, `NullPool`); migrations and worker use the direct endpoint.
- **Vercel serverless API**: single Python entrypoint (`api/index.py`, `maxDuration: 300`).
- **Render worker**: HTTP entrypoint (`GET /health` public, `POST /wake` bearer-authenticated) + outbox sweep loop; `CELERY_TASK_ALWAYS_EAGER=true`; free-tier keepalive pings `WORKER_PUBLIC_URL` while a sweep is running.
- **Outbox**: executions record `ExecutionQueuedEvent` in the same transaction as the execution row; worker sweeps with `FOR UPDATE SKIP LOCKED`.
- **Wake**: after commit the API sends a fire-and-forget `POST /wake` (bearer `WORKER_AUTH_TOKEN`) to the worker.

## Known limitations (v1)

- Render free tier: cold starts (~30–90 s), ~15 min idle sleep, no automatic recovery if an instance is killed mid-run (execution left `RUNNING`).
- Single worker, serial task processing.
- Vercel function cap of 300 s; long-running work must stay in the worker.
- Agent tasks run in-process on the API background thread and may not survive serverless request teardown — safe for short interactions only.
- Grok provider disabled (account/model validity); re-enable is tracked.
- Cosmetic: execution-list `completed_items` counter can lag batch-reported results; status/results are accurate.
