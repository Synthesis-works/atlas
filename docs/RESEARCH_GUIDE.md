# Atlas Research Guide

Atlas has evolved into a fully-fledged, reproducible, lightweight AI evaluation research framework. This guide outlines how to use Atlas for running scientific experiments, analyzing failures, and comparing models.

## How to Reproduce Experiments

Every experiment generated by `run_experiment.py` logs an `experiment_config.json` inside its results folder (`results/experiments/<exp_id>`). 

This config captures:
* **Dataset** (e.g. HumanEval)
* **Model** (e.g. `qwen2.5-coder:1.5b`)
* **Prompt Version** (e.g. `v3`)
* **Seed** (e.g. `42`)
* **Git Commit Hash** (e.g. `a1b2c3d4`)
* **System Metadata** (Python version, Ollama version, Model Digest, OS, CPU, RAM)

To reproduce a run perfectly, checkout the Git commit from the config, ensure the same model digest is active in Ollama, and run:

```bash
py scripts/run_experiment.py --dataset HumanEval --prompt v3 --model qwen2.5-coder:1.5b --seed 42
```

## How to Compare Experiments (Prompt Benchmarking)

To understand if Prompt B is statistically better than Prompt A, do not just compare Pass@1. Use the `compare_prompts.py` script:

```bash
py scripts/compare_prompts.py --jobs exp-v1-abc exp-v2-xyz exp-v3-123
```

This generates `prompt_comparison.md` and `prompt_comparison.png`, calculating 95% Confidence Intervals (Wilson score interval) to prove statistical significance. It also compares token counts, latency, and extraction failures.

## How to Analyze Failures (Semantic Clustering & Logic Breakdown)

When a model fails on 96 out of 164 tasks, manual inspection is impossible.

**1. Semantic Clustering:**
Use `cluster_failures.py` to embed all failed tasks, cluster them using KMeans (automatically finding the best K via Silhouette score), and extract TF-IDF keywords.

```bash
py scripts/cluster_failures.py --job exp-humaneval-de17ee
```

This reveals whether a model struggles with "Dynamic Programming" vs "Parsing".

**2. Deep Logic Breakdown:**
Instead of counting "46 logic errors", use `analyze_logic_errors.py` to apply deterministic rules (and LLM fallback) to categorize errors (e.g., *Wrong Algorithm*, *Boundary Error*, *Infinite Loop*).

```bash
py scripts/analyze_logic_errors.py --job exp-humaneval-de17ee
```

## How to Find Nearest Successful Tasks

To run an automated ablation study on difficulty, `NearestNeighborSuccessFinder` queries the embeddings of passed tasks to find the closest match to a failed task. 

*Example:* If "Reverse Parentheses" failed, the Nearest Neighbor tool might find "Balanced Parentheses", helping you trace exactly where the model's reasoning boundary broke down.

## How to Add a New Benchmark

1. Create a new importer script in `packages/datasets/importers/`.
2. Implement the importer to map the raw dataset format into `DatasetPack` and `DatasetTask`.
3. Update `packages/experiments/runner.py` to instantiate your new importer when `--dataset <name>` is passed.

## How to Add a New Prompt / Model

**Prompts:**
Atlas uses a Prompt Registry. Drop a new markdown template (e.g., `v4.md`) into `prompts/` and register its structure in `prompts/metadata.json`. You can immediately benchmark it using `--prompt v4`.

**Models:**
Atlas is provider-agnostic. Pass `--model deepseek-r1:1.5b` (if available in your local Ollama instance) to immediately benchmark it across your dataset. All metadata will automatically track the new model.
