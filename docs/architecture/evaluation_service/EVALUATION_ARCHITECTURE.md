# Evaluation Architecture

## Overview
The Evaluation Service is responsible for assessing the outputs generated by the Execution Service. It transforms raw text outputs into standardized metrics, which are then aggregated to derive benchmark-agnostic intelligence capabilities.

## Architecture Pipeline

1. **Job Creation**: Triggered by `RUN_COMPLETED`. `EvaluationOrchestrator` creates an `EvaluationJob`.
2. **Attempt Lifecycle**: `EvaluationAttempt` handles the specific configuration (pipeline version) being tested.
3. **Pipeline Execution**: Specific pipelines (`JudgePipeline`, `ExecutionPipeline`) take raw outputs and output `EvaluationResultBundle`.
4. **Metric Standardizing**: `MetricEngine` validates and normalizes these values.
5. **Capability Derivation**: `CapabilityEngine` aggregates normalized values to derive human-readable intelligence profiles (Coding, Reasoning, etc).

## Constraints
- Strict one-way dependency from Execution to Evaluation.
- Evaluation models do not back-reference execution runs with foreign keys pointing the other way.
