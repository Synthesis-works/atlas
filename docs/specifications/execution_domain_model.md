# Execution Domain Model

This document outlines the Domain-Driven Design (DDD) aggregate roots and internal entities for the Phase B Execution engine.

## Aggregate Root: `Execution`
The core entity around which the entire workflow engine resolves. Users don't think about "creating a job"—they think about "running a benchmark execution."

**Attributes:**
- `id`: UUID (Primary Key)
- `benchmark_version_id`: UUID (The specific, published benchmark being executed)
- `status`: Enum (`QUEUED`, `SCHEDULED`, `RUNNING`, `COMPLETED`, `FAILED`, etc.)
- `created_by`: UUID (User who submitted the execution)
- `created_at` / `updated_at`

### Child Entity: `Lease`
Represents the current lock held by a distributed worker over this execution. An execution can have at most one active lease.

**Attributes:**
- `id`: UUID
- `worker_id`: UUID (ID of the node processing the execution)
- `acquired_at`: Timestamp
- `expires_at`: Timestamp (Updated on every successful heartbeat)

### Child Entity: `ExecutionAttempt`
Maintains the history of execution failures and retries. Every time an execution transitions from `QUEUED` to `SCHEDULED`, a new Attempt is created. Once finished (failed or completed), an attempt becomes strictly immutable.

**Attributes:**
- `id`: UUID
- `attempt_number`: Integer
- `started_at`: Timestamp
- `finished_at`: Timestamp (Nullable)
- `status`: Enum (`SUCCESS`, `FAILED`)
- `error_message`: String (Nullable)

### Child Entity: `Artifact`
References to outputs generated by the execution (e.g. model logs, dataset inferences). Every artifact belongs to exactly one `ExecutionAttempt`.

**Attributes:**
- `id`: UUID
- `attempt_id`: UUID
- `type`: Enum (`LOGS`, `MODEL_OUTPUT`, `EVALUATION_RESULT`)
- `storage_uri`: String (S3 path or similar blob reference)

### Child Entity: `Evaluation`
The final score or assessment generated for the execution. 

**Attributes:**
- `id`: UUID
- `score`: Float/JSON (Metric output)
- `strategy_used`: UUID (Reference to the evaluation logic applied)

## Relationship Map
```
Execution (Aggregate Root)
│
├── Lease (1:0..1)
├── Attempts (1:N)
│   └── Artifacts (1:N)
├── Events (1:N)
└── Evaluation (1:0..1)
```

## Internal Rules
- `Execution` encapsulates all state mutations. A service modifying a lease must do so by modifying the `Execution` root to ensure invariants (like "no two active leases") hold true.
- Repositories must always fetch the entire `Execution` aggregate (using necessary joins or lazy loading policies) before persisting state transitions.
