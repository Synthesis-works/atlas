# System Boundaries

## Execution Engine
**Responsibility**: Run generated code inside isolated containers, track execution state, manage workers.
**Boundaries**:
- Does NOT know what a "score" or "metric" is.
- Does NOT know what an "EvaluationJob" is.
- Outputs `ModelOutput` (raw text, duration, tokens).
- Communicates outward via `RunEvent` (e.g., `RUN_COMPLETED`).

## Evaluation Engine
**Responsibility**: Take raw outputs, apply judging pipelines, calculate metrics, derive high-level capabilities.
**Boundaries**:
- Reads from `ModelOutput` generated by Execution.
- NEVER writes back to Execution models.
- NEVER alters the state of an `AtlasRun`.
- Listens to Execution's `RunEvent`s to trigger its own `EvaluationJob`.

## Data Isolation
- Execution and Evaluation share the same physical database (for now) but maintain strict schema separation.
- Foreign keys from Evaluation to Execution are permitted (e.g., `EvaluationJob` -> `AtlasRun`).
- Foreign keys from Execution to Evaluation are FORBIDDEN.
